# 漫和居公寓房源展示系统 · 小白操作手册

> 第一版不用买服务器、不用买数据库套餐、不用买域名。先用免费方案上线测试。
> 你拿到的是一个 `dist` 文件夹（网站本体）+ 一个 `supabase/schema.sql`（建表脚本）+ 这份手册。

---

## 一、先看懂这个系统长什么样

- **客户看到的**（不用登录）：
  - 首页 `index.html`：全部门店列表
  - 门店页 `store.html?store=英文名`：一家店一个链接，只看这家店的房型图/视频 + 当前可租房源
- **你管理的**：`admin.html` 后台，邮箱+密码登录才能进
- **数据放哪**：Supabase（免费版云端）。换电脑打开后台登录，数据都在。
- **没配置 Supabase 之前**：网站自动进入**演示模式**，用示例数据完整预览效果，后台改动只存在当前浏览器里，不要在演示模式录正式数据。

演示模式后台进入方法：打开 `admin.html`，填任意邮箱 + 任意 6 位以上密码即可。

## 二、上线分三步（约 30 分钟）

### 第 1 步：建 Supabase（数据 + 管理员账号）

1. 打开 supabase.com，注册/登录，新建一个 Project（名字随便，如 manheju），选离得近的区域，设置一个数据库密码并记好。
2. 等项目建好后，左侧点 **SQL Editor → New query**，把 `supabase/schema.sql` 文件里的**全部内容**粘贴进去，点 **Run**。看到 Success 就说明：5 张表、权限（RLS）、2 个图片存储桶、5 家初始门店都建好了。
3. 建管理员账号：左侧 **Authentication → Users → Add user / Invite user**，填你的管理员邮箱。对方邮箱会收到邀请邮件（这就是“首次设置密码”：点邮件链接设密码）。
4. 把这个人加进管理员白名单：回到 SQL Editor，运行这一段（邮箱换成你的）：
   ```sql
   insert into public.admin_users (user_id)
   select id from auth.users where email = '你的管理员邮箱'
   on conflict do nothing;
   ```
   > 没做这一步，后台会提示“不在管理员白名单”进不去，这是故意的，防止别人注册了就能改数据。
5. 拿钥匙：左侧 **Settings → API**，记下 `Project URL` 和 `anon / publishable key`。
   ⚠️ 同一页还有一个 `service_role` 密钥，**绝对不要**把它填进网站或发给任何人。

### 第 2 步：把钥匙填进网站（只改一个文件）

打开 `dist/js/config.js`，只改两行：

```js
supabaseUrl: "https://你的项目.supabase.co",
supabaseAnonKey: "eyJ开头的anon钥匙",
```

保存。以后迁移到腾讯 CloudBase 也只动数据层，不用重做页面。

### 第 3 步：部署到腾讯 EdgeOne Pages（免费）

1. 打开腾讯 EdgeOne Pages，创建一个免费项目，选择**上传文件夹 / 静态文件**方式，把整个 `dist` 文件夹上传。
2. 部署完成后它会给你一个免费网址，如 `xxx.pages.dev` 之类（项目名部分可改，后缀是平台的，不能完全自定义）。
3. 用这个网址打开：首页能看到 5 家门店 = 成功。再打开 `网址/admin.html` 用管理员邮箱登录试一下。

> 提醒：之前那个 chatgpt.site 域名在部分手机流量下会被拦截，不要用它做正式客户入口。

## 三、日常怎么用（管理员）

### 新增一家门店
后台 →「门店」→ 填名称、英文短链接（slug，只能小写英文和 `-`，如 `guanggu-dong`）、起租价、地址、交通、地标、简介、**首页优势标签**（逗号分隔，如“精装,拎包入住,地铁100米”，首页每店最多显示4个）→ 保存。
> 首页是紧凑列表版：一屏能看多家店，客户按店名+地址+优势自己挑，点进去才看大图和空房。
列表里每个门店右边有**「复制链接」**，把这个链接发微信群/朋友圈/短视频主页，客户点开只看这家店。

### 停用 / 删除门店
编辑门店时取消勾选“对客户显示”就是停用（客户看不到，后台数据还在）。
删除需要点两次确认，且会连房型、图片、空房一起删，慎用。

### 上传房型图片/视频
后台 →「房型与图片视频」→ 先选门店 → 新建房型（名称、简介、亮点标签用逗号隔开）→ 保存后，在房型卡片下方选文件上传，可多选、可调顺序。
- 每家店拍 3–5 个房型，传一次即可，不用每个房号都传图。
- **视频别传 4K 原片**：先压缩，单条尽量 10–30MB，手机上才加载得快。

### 维护每天的空房（最常用）
后台 →「实时空房」→ 选门店：
- **一条条改**：填房号、房型、月租、管理费（默认150）、状态、公开备注 → 保存。
- **批量导入**：从 Excel/WPS 里选中多行复制，粘贴到批量框 → 导入。列顺序必须是：`房号、房型、月租、管理费、状态、公开备注`，状态写中文“可租/已预订/已出租/维修中”就行。
- 客户**只能看到**“公开 + 可租”的房源。租出去了就把状态改成“已出租”，客户页立刻就看不到，不用删。

### 原始价格表存档
后台 →「原始价格表」→ 上传微信群里的空房表截图。这里只有管理员能看，客户看到的永远是整理后的空房表。

### 忘记密码
后台登录页填邮箱 → 点「首次设置密码 / 忘记密码」→ 邮箱收到链接 → 点开回来设置新密码。

## 四、上线后必须做的真机测试

用**你自己的手机**逐项测，不要只在电脑上看：

1. 关 Wi-Fi 用流量打开首页和一个门店链接；
2. 用微信内置浏览器（发给自己的微信点开）再打开一次；
3. 检查：图片/视频能播、空房表看得清、已出租的房子不显示；
4. 如果 Supabase 在你的网络下明显很慢（转圈很久），告诉开发方，需要评估迁移腾讯 CloudBase。

## 五、以后想升级时

- **想要自己的域名**（如 manhejuwh.com）：域名按年购买，在大陆长期用还要**备案**，再绑到 EdgeOne Pages。第一阶段先别买。
- **数据迁 CloudBase**：网站的数据读写都集中在 `dist/js/data-service.js` 一个文件，迁移时只换这一层，页面和后台不用重做。
- **房源涨到几千套**：现有结构（门店→房型→房号）不用改，后台可无限加门店。

## 六、常见问题

- **后台登录提示不在白名单** → 做第二步第 4 小步，把邮箱加进 `admin_users`。
- **客户页是示例数据** → `config.js` 还没填 Supabase 钥匙，正处在演示模式。
- **图片传不上去** → 多半是 schema.sql 没运行成功（存储桶不存在），重跑一遍 SQL。
- **改了价格客户没看到** → 先确认状态是“可租”且勾了“公开”，再刷新客户页。
